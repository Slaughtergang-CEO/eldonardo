Enterprise Architecture

Spezifikationen & Datenbankschema

Unsere Systeme basieren auf verifizierten Enterprise-Komponenten. Hier sehen Sie die schematische Implementierung der Supabase-Sicherheitsarchitektur für den oben integrierten Marktplatz.

POSTGRESQL SCHEMATA (SUPABASE)
TABLE: products
id: uuid (Primary Key)
title: text
slug: text (Unique)
description: text
price: numeric
category: text (Check constraint)
preview_image_url: text
file_download_path: text (Private Bucket Link)
TABLE: purchases
id: uuid (Primary Key)
user_id: uuid (FK auth.users)
product_id: uuid (FK products.id)
stripe_session_id: text
purchased_at: timestamp
ROW LEVEL SECURITY (RLS) POLICIES
POLICY 1: Public Read Access on 'products' CREATE POLICY "Allow public read access" ON products FOR SELECT USING (true);
POLICY 2: Protected Download Validation

Der Zugriff auf private Buckets wird serverseitig via RLS validiert, indem ein gültiger Purchase-Eintrag in der Transaktionsdatenbank nachgewiesen werden muss.

CREATE POLICY "Allow downloads for verified buyers"
ON storage.objects FOR SELECT
USING (
  bucket_id = 'private_assets' AND
  EXISTS (
    SELECT 1 FROM purchases
    WHERE purchases.user_id = auth.uid()
    AND purchases.product_id = (SELECT id FROM products WHERE file_download_path = name)
  )
);
